# ADR 0004：普通四川计分的文案优先与补充约定

状态：采用，仅适用于5022血战到底与5021普通血流；不适用于红中血流、日麻或扑克。

## 依据与范围

用户要求优先采用原客户端可阅读的规则，并授权统一处理缺失或冲突细则。原页面、文本ID、倍率与生成方式集中在 `mockjs/sichuan_catalog.mjs` 和 `docs/multigame-backend-plan.md`。原表 `ExceptYis` 存在自引用和跨玩法引用，不能直接执行为互斥算法。

公开四川规则检索可确认存在多种自摸、加番与组合计分版本，但未取得与本客户端完全相同的权威补充说明。因此以下有争议的组合明确视为**本地约定**，不宣称是所有四川麻将的统一规则。原页面明确的倍率不按其他平台改写，例如将三龙七对保留126倍。

5022血战与5021普通血流共用 `SichuanEngine` 局序，按 `gameType` 区分胡后离场或继续；两者均已接通原UI通知、匹配、重连与雀币结算。5023红中血流同样共用该局序，其赖子、红中杠与补充约定见 [ADR 0005](0005-red-zhong-xueliu.md)。

## 计分决策

1. **择优而非相加**：枚举合法牌形，分别乘算后取最大未封顶倍率；标准胡与七对不叠加。最后统一封顶，保留原始倍率与封顶标记。房间须明确传入封顶值，不能沿用日麻满贯/役满算法。
2. **复合番替代组成项**：依原“不计……”文案去掉已包含的低级番；更高级的复合番同样替代其组合形式，例如清十八罗汉不能再保留清金钩钓。七对按实际0/1/2/3组四张选择龙级别；清双龙、清三龙没有独立可见条目，采用清一色乘双龙/三龙，不再乘清七对或清龙七对。
3. **根不重复收费**：暗手和副露合计四张同种算一根，包括四归一。龙级别已含的根不再乘；十八罗汉已含四根。将七对原文排除龙七对但未单列根，本地约定其倍率已包含第一根；将双/三龙相应含二/三根。其他未被复合番包含的根每根乘2。
4. **未被排除的附加番相乘**：清一色、断幺九等可与未包含它们的牌形相乘；将对/将七对体系不另计断幺九。原文没有将对与金钩钓/十八罗汉互斥，本地按其完整倍率相乘（32/512倍），但不再加碰碰胡、断幺九或已包含的根。最终仍受房间封顶约束。
5. **幺九按标准面子判断**：每个刻子、顺子和将必须包含1或9。七对没有四面子结构，不仅因每对都是幺九牌便额外加此番；如可另分解为标准胡，则独立评分择优。
6. **情境番的补充边界**：天胡/地胡32倍视为已包含自摸，不再乘自摸2；可以与独立牌形相乘。两者不与已有副露、杠上花、海底混用。普通自摸、杠上花与海底在同一最终补牌满足定义时可相乘，不套日麻岭上排除海底的规则。海底只用于自摸，最后一张舍牌荣和不另加海底。抢杠只按权威传入的补杠抢和情境计分。
7. **查大叫不虚构机会役**：枚举实体牌上可能存在的等待，取最大普通荣和牌形倍率，不假设自摸、抢杠、开局或海底。自己已持四张的第五张不能算等待；其他玩家已经公开全部剩余牌仅影响AI受入，不取消形式听牌。

## 支付与调用边界

- 和牌倍数按上述规则先封顶，再乘底分。自摸由仍在局的对手逐家付款；荣和仅点炮者付款，庄家不额外加倍。血战已胡退出者不再承担后续和牌/杠费；血流由局序继续将已胡者列为在局。
- 明杠仅放杠者付两底；补杠每家一底；暗杠每家两底。原“能明杠而先碰再补”由局序记录，支付器仅接受补杠免收标记。抢杠成功前不能先提交补杠收款。
- 返回独立的四座位增量和逐笔转移，不写档案或余额；拒绝无效座位、重复/稀疏列表、非安全整数与溢出。多响必须由局序收齐响应后统一提交，不能边问边扣。
- `scoreSichuanHand()` 的情境参数只由权威状态生成，不接受客户端直接提供的番数或自报天胡。`maxSichuanReadyScore()`刻意不接受这些情境奖励。
- `SichuanEngine` 在副本上完成校验后的整次状态转换，成功才替换权威状态；`windowId` 绑定当前动作窗口。同一响应窗口内每席只收一次，全部响应收齐后统一处理多响。该内部窗口编号不等于尚待核验的外层 `GameNumber`。
- `snapshot()` 包含暗手、未来牌和完整事件，只用于服务端诊断/测试，禁止发给客户端或AI。`view(seat)` 排除未来牌、他家未公开暗手和暗杠实体；AI只消费该本人视图。

## 血战局序与荒牌补充约定

1. **终局**：三家已胡或无牌可继续摸时结束；最后一张先允许自摸与舍牌荣和，再荒牌清算。无牌可补摸时不允许杠，也不允许继续碰牌。胡牌退出者保留本人实体牌，但不再行动或承担之后和牌/杠费；荣和牌保留单一实体归属，多响只有共享引用。
2. **定缺与鸣牌**：手中有缺门则弃牌候选仅包含缺门。碰/杠目标不得是缺门，局部约定不额外要求先清空全部缺门才可碰其他花色；自家杠仅在开局或实际摸牌后提供，碰后先弃牌，不能不摸牌直接补杠或暗杠。
3. **过胡（原文缺项，本地约定）**：在下一次本人摸牌/杠补牌前，放弃和牌后只允许倍率更高的荣和；以实际封顶后倍率比较，包含放弃自摸时的情境番。碰后弃牌不解除，下一次本人摸牌解除。没有资格和牌时不制造过胡。
4. **补杠与抢杠**：仅补杠可抢，不借用日麻国士抢暗杠。无人抢和才把第四张加入原碰并收杠费；被抢时原碰不变，第四张单独保留为被抢实体。曾能明杠却先碰的实体副露，后续补杠免收费用。
5. **天胡/地胡**：庄家初始14张自摸视为天胡；闲家首次摸牌、本人尚未弃牌，且此前没有碰杠或胡牌中断时为地胡。換三张/定缺本身不打断；换走庄家原第14张后，展示引用必须改为本人仍持有的实体牌。
6. **呼叫转移**：杠后紧接舍牌造成单响，转移当次实际收取的全部杠费；一炮多响不转移。连续杠只转移最近一次杠收入，不累加之前的杠（原文未细分，本地约定）。已转移的收入不能在荒牌时再由原收杠者退一次。
7. **退税**：荒牌时，未胡且未听或仍有缺门的收杠者，把未转移的杠收入按原始账目逐笔退给实际付款人，包括后来已胡者；已胡者和听牌者保留杠收入。
8. **查大叫**：仅未胡、无缺门且未听者，向每位未胡听牌者赔其最高普通荣和倍率乘底分；无自摸/抢杠/海底机会番。花猪不叠加查大叫（本地约定，避免同一荒牌状态双重处罚）。
9. **花猪**：按原文16倍底分赔每位非花猪，包括已胡者；花猪之间不互赔。确实至少出过一次牌且每次都在打缺门，免花猪费；该豁免不免退税，也不把花猪变成可收查叫的听牌者。
10. **经济边界**：目前仅计算守恒的局内积分，不实施钱包扣款、破产、补豆或继续局，也不写日麻段位/战绩。它们必须在会话接线阶段单独完成；不能用负钱包或假成功掩盖未实现流程。

## 普通血流（5021）补充约定

原文只给出“每个玩家可多次胡牌，直至摸完所有手牌，胡牌时直接结算”和“血流封顶：免费场5120倍、其它场10240倍”，以下为本地补全：

1. **胡后不离场**：胡牌者继续摸打，仍列入后续自摸、杠费的付款人；终局只有牌墙摸完一种（`endReason='wall'`）。下一位摸牌者与血战一致：自摸后为胡者下家，荣和后为放铳者下家。
2. **胡牌区**：自摸张移出暗手进入胡牌区，暗手回到13张；荣和张仍是放铳者河中实体。`wins` 逐次记录，终局 `huInfos` 逐次列出；`NtfPlayCard/NtfQiangCardEnd` 的 `isFinish` 与终局 `isFinish` 均为 false。
3. **胡后锁牌**：已胡者不得改变胡牌牌形。轮到本人时只能打出刚摸到的实体牌、再次自摸，或杠；不能碰。杠（暗杠、补杠、点杠）必须包含刚摸到/被打出的那张，且杠后听牌种类与杠前完全一致。过胡与未胡者相同。
4. **封顶**：单次和牌仍按房间128/256封顶（原表5021房间封顶字段与血战相同）。5120/10240恰为128/256的40倍，按“每家整局累计净输分不超过40倍单次封顶×底分”执行；超出部分不支付，账目只记实付额，退税与呼叫转移也只按实付额进行。
5. **荒牌清算**：已胡者不再被查叫，也不收查叫款；花猪、退税规则与血战相同。
6. **离桌**：血流胡后仍要继续承担付款，只有终局后才能离桌；血战胡后可离桌。

## 血战会话的本地计时约定

`SichuanSession` 当前默认准备20秒、换三张20秒、定缺15秒、摸打15秒、响应10秒，均为各阶段独立期限，不继承日麻5+20共享时间。这些是尚未接入原UI的本地默认值，不宣称还原原服房间计时；协议接线时应核实原房间配置和客户端秒数/截止时间字段。

真人响应超时默认过牌；摸打超时优先合法摸切，仍有缺门时强制打缺，不自动胡/杠。换三张/定缺超时由公平AI选择。断线或主动托管则由AI正常决策，同进程重连保留当前截止时间；旧连接、旧窗口和被取消的定时任务不能提交新动作。准备阶段断线也会由AI开始并完成本单局。

会话只提供过滤后的本人视图与一次性终局摘要；服务端必须单独绑定连接代次、入站动作窗口和请求去重，不能把客户端未写入的 `GameNumber` 当作窗口编号，也不能声称现有传输已具备这些接线。

## 验证

`test/sichuan-score.test.mjs`覆盖原27种可见番型、复合排除、根、多分解、126原值、封顶、查大叫、情境冲突、三类杠款、在局付款、守恒、溢出与输入不变。

`mockjs/sichuan_ai.mjs`只接收本人暗手/副露和公开实体牌，向听为策略排序估计，不作为权威和牌依据。只复用日麻的标准四面子向听底层算法；四川七对另算，缺牌不参与牌形，零向听须复核实体等待。`test/sichuan-ai.test.mjs`覆盖上述边界、隐藏字段访问陷阱及固定种子100手合法性检查，不宣称棋力搜索最优。
