# ADR 0011：补齐和牌结算逐条显示役种用的静音提示音

状态：已采纳（2026-10-24）

## 背景

和牌结算面板逐条亮出役种，每条之间的停顿由和牌者的语音序列 `NPCxx_000_{JP,CN}`（`npcxx_aud_{jp,cn}` 包里的 SkillEditor 序列）控制：它播放游戏自带的静音片段 `Assets/ArtAB/globbyab/co/aud/common_01/Empty_s.asset`（约 0.5 秒），播完才亮下一条。

角色 6（Toki/Sumire 的模型 NPC06）和角色 9（Kana/Toyone 的模型 NPC09）的这条序列里，音频事件的片段引用是空的（日文、中文版都是）：序列长度为 0，所有役种在同一帧弹出。其余 8 个角色都引用 `Empty_s`。语音片段本身（`mj_jp_aud_npcxx_*`）、各角色的其余序列和配置都完整，不是“缺语音”。

实测（2026-10-24，隔离有界面 Edge，固定种子让 Kana 自摸，按 250 ms 截屏，并钩住 WebAudio 记录播放）：Koromo 和牌时每条役种都播一次 0.4963 秒的 `Empty`，役种约每 0.39 秒亮一条；Kana 和牌时没有任何 `Empty` 播放，5 条役种和总番数同时出现。

## 决策

- 用游戏自己的静音片段，不新合成语音，也不依赖外部工具。`tools/build_settlement_titles.py` 沿用 ADR 0010 的派生流程：校验原包固定 MD5，把 NPC06、NPC09 的 `NPCxx_000_{JP,CN}` 换成 NPC04 同名序列（同一布局；NPC04 与 NPC05 的这条序列除名字外逐字节相同）并改成自己的名字，核对包内其他对象原始数据不变；生成哈希命名的派生包，派生清单里只改这 4 个包和 `mjab_jp_ui_ingame` 的 hash/size。
- 仍只有一份派生 `versions.mj.json` 与一份派生清单；原包、原清单不动。

## 代价与边界

- 只修复役种逐条显示的节奏；这两个角色和其他角色一样不念役名（国际版各角色都只播静音片段）。
- 构建依赖与 ADR 0010 相同（开发机临时 UnityPy==1.25.4）。Unity 快照变化时固定 MD5 校验失败，需要重新审计。
