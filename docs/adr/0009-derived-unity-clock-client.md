# ADR 0009：用哈希固定的派生 WASM 让原客户端显示权威剩余时间

状态：已采纳（2026-10-23）

## 背景

引擎的单窗口真人时钟（`GameEngine._humanClock`）已统一公告、超时、备用扣费和重连快照。原 Unity 客户端在 `InitCountDown` 里按收到的 `defaultMinTimeout` / `leftTimer` 算出三个绝对截止点；协议里没有暂停、续时或重设时钟的消息，JS 也没有可调用的计时接口。抢杠/抢北等切点生成不了局面快照，只能退回整手重放，客户端会按历史公告重新从“5+20 秒”起算，比服务端晚超时。

## 决策

- 不修改原件 `Build_intl/mj-h5.wasm.unityweb`（SHA-256 `730effb3…cab9`）。构建工具校验原件后，在 InitCountDown（39470）、UpdateTimeText（14666）插入 `mj.clock` 计时投影与可操作信号；`mj.sync` 观察通知（35847）、渲染（21653）、Reload（35819）和状态切换（4571）。v3 额外修正备用耗尽的原生显示分支，导出保持不变。派生文件和 `mj-h5.clock.json` 随仓库提交，运行时不需要构建工具。
- `clock-bridge.js` 经 Unity loader 已有的 `Module.instantiateWasm` 钩子加载派生文件，先校验清单和 WASM 哈希。清单声明的来源哈希或派生文件对不上时直接中止启动（原件本身由派生构建和回归测试校验），**不静默回退**到会显示错误时间的原客户端。不覆写全局 `WebAssembly`。
- 时钟投影 `{id, baseMs, extraMs, running}` 只来自 `GameEngine.humanClockState()`：静态宿主直接读页内引擎；Node 宿主在同一条游戏 WebSocket 上发 JSON 文本帧，`offline-patch.js` 在交给 Unity 前吞掉。三次读取共用同一份毫秒样本、向上取整，服务端 3 秒宽限不进入客户端显示。
- 恢复使用 `{mjSync: …}` / `{mjSyncAck: …}` JSON 侧带，不改变原 protobuf 消息。服务端为当前 socket 分配同步批次 UUID，实际投递末帧后发送其 `f27` 计数。派生客户端须已消费该帧、渲染队列空闲；快照另须对应状态机离开 Reload(9) 返回 Gameplay(4)，再经历两次绘制机会才回 ACK。服务端核对连接、批次及计数，期间若有新增牌局帧则另开追帧批次；没有确认只保持冻结并在超时后重连，不用固定延时解冻。控制侧带不送进 Unity 的 protobuf 解码器。
- Reload 实际经 HybridCLR 运行，不能挂在未执行的 AOT 异步状态机副本；钩子观察 Reload 分发期间进入状态 9 的那个状态机，只有同一对象成功回到状态 4 才能完成。
- Node 服务给派生文件加 `Content-Encoding: br`、`Content-Type: application/wasm`，Cloudflare `_headers` 的 `*.wasm.unityweb` 规则同样覆盖它；没有编码头的静态托管则由文件内嵌的 Unity Brotli 标记交给 loader 解压。

### 计时与后台行为修正（2026-10-23，用户实测反馈）

每小局（含连庄）庄家首手基础 8 秒，其他决策 5 秒，加本小局共享 20 秒备用。v3 通过原生 InitCountDown 就绪信号绑定当前窗口：前台渲染完才起表，发牌动画不扣时；后台新窗口不依赖 rAF，保持连接正常时照常推进。基础与备用分别向上取整，基础阶段“+N”恒定。备用耗尽时仍在基础阶段，不显示“5＋0”；原生按“+N”是否可见选颜色，派生只在“基础阶段且无备用”时补选白色基础样式，备用阶段仍为黄色，引擎基础/备用账目不变。原生 `OnTimer` 每帧调用一次显示刷新，读取权威余量；一秒节拍只保留给原有音效与到点判断，避免首个“5”因节拍错位停留 1～2 秒。真正断线及恢复过程冻结。每页面身份将冷启动与同页恢复分开：冷启动先用既有 20408/20014 进桌、等 ReqPrepare 再整手重放；同页才尝试快照。恢复仍须实际消费、渲染和 Reload 确认，不靠固定等待或补时绕过门禁。

## 理由

- 不重写 C# 状态机：计时只覆盖三个截止点，同步钩子只观察现有客户端真实执行，不替代重放、超时动作和按钮逻辑。
- 哈希固定让 Unity 升级后立即失败而不是带病运行；派生过程可重复，原件始终可回溯。

## 代价与边界

- 派生文件与当前国际版强绑定。升级 Unity 构建时必须重新核对计时、通知、渲染、Reload 与状态机钩子和内存偏移，再跑 `npm run build:clock` 和测试。
- 构建工具需要开发机临时使用 npm 的 `wabt@1.0.39`，以及 Python `wasmtime==50.0.1`、`brotlicffi==1.2.0.0`；它们不是项目依赖。
- 中文归档客户端（`archive/zh-client/`）没有接入桥接。
- 独立审查发现的提前解冻与后台新窗口等待 rAF 停表均已修正并有回归。隔离 Edge 验证 Node 四麻的真实关闭重开、同页恢复，以及静态三麻的关闭重开；确认前计时仍冻结。两次绘制机会不代表物理屏幕呈现。当前派生 SHA-256 `0d6b04dfe140c028cf42811cd9c1af96e35768a75cc73fe317d1224bca07083e`，重复构建一致；原件未改。
- 2026-10-23 已在隔离 Edge 中从正式 `game.html` 验收两种宿主（静态三麻、Node 四麻）：冻结后强制整手重放保留余量，当时续时后原客户端自己在 33 秒左右发出超时（该历史验证含已撤销的首手 8 秒补偿，不能作为当前 25 秒契约的验收证据），下一窗口仍是 5 秒基础段，用掉约 2 秒后再重放仍显示 3 秒。整手重放是通过禁用快照强制触发的；没有自然触发抢杠/抢北，也没有验收真实的系统级后台切换或移动端。
