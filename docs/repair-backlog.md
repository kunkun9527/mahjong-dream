#### 逐提交不变量的存储模型与边界

`test/helpers/invariants.mjs` 只读牌局数据，包装实例方法记录检查，不更改原型、牌山、AI 决策、动作返回值或执行流程。观察点包括发牌完成、摸牌后进入 `awaitTurn`、弃牌后进入 `discard`、吃碰后动作窗口、杠/拔北后进入补牌、补牌同步提交、输入窗口消费、过荣和/立直确认、结算参数提交及 `finishHand` 分数落地；不再只依赖通知回调，也不把单个数组 splice 的未完成中间态误作一次完整动作。

- `deadWall` 是初始索引快照：前 4/8 张与岭上牌重叠，不重复记所有权；后十张全部（含尚未翻开的宝牌/里宝）逐实体计入。
- 每次补牌封存的牌山尾牌由观察器逐实体记账，不再只用缺张数量推断；抢杠/抢北的和牌实体归终局参数区，不复制进各赢家手牌。
- 结算先在局部 `scores` 上计算，再在 `finishHand` 写入 `this.scores`；`players.score` 保留本手缓存，检查不会混加不同时刻的两本账。
- 检查实体全集/唯一性、点数加供托、最多一个可弃牌座位、实际动作执行座位、唯一输入窗口与缓冲、窗口供牌实体及等待任务关联。复制实体、双窗口、双行动者、非法动作部分提交、宝牌区重复/缺牌/点数变化均有负向自检。
- 非法请求比较引擎全部自身数据字段的深拷贝；运行时函数不入快照，等待任务保留种类/开始时间/计时器存在性，并单独比较等待任务、计时器及回调身份。原协议没有客户端 seat 或 windowId 字段，错误座位通过无法建立真人窗口验证，过期窗口指已关闭/已消费窗口；不声称能识别另一新窗口中内容恰好相同的旧请求。

#### 新测试确认的缺陷
